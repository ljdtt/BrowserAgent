# BrowserAgent 工程增强设计

## 1. 背景与目标

BrowserAgent 当前已经具备 Qwen 模型调用、Playwright 浏览器控制和 Streamlit 界面的基本骨架，但核心执行链还存在点击缺失、元素编号不一致、页面正文未正确反馈、失败状态不明确和执行过程不可观察等问题。

本次改造面向 AI 应用／Agent 开发岗位，目标是将项目完善为一个可运行、可复现、可评测的浏览器智能体。项目重点展示以下能力：

- 将自然语言任务转换为结构化浏览器操作。
- 基于页面观察结果进行多轮决策和工具执行。
- 对工具错误、无效动作和执行上限进行受控恢复。
- 保存并展示每一步的操作、页面状态、截图、耗时和结果。
- 使用固定任务集和确定性验收条件评估任务成功率。

本阶段保留 Python、Qwen-Agent、Playwright 和 Streamlit 技术栈。LangGraph 对比作为后续独立扩展，不进入本阶段完成标准。

## 2. 范围

### 2.1 本阶段包含

- 修复并统一导航、点击、输入、回车和滚动操作。
- 为页面上的可交互元素分配单一、稳定于当前观察快照的元素标识。
- 使用结构化 JSON 动作协议约束模型输出，并在执行前校验动作参数。
- 实现任务运行状态、错误反馈、有限重试、重复动作检测和最大步数终止。
- 在 Streamlit 中显示配置、任务状态、步骤轨迹、截图、耗时和最终结果。
- 建立本地确定性演示页面、自动化测试和小规模评测任务集。
- 修订 README 和简历描述，使功能描述与实际验证结果一致。

### 2.2 本阶段不包含

- 登录真实账户、验证码处理、支付或不可逆网页操作。
- 多智能体协作、RAG、向量数据库或长期记忆。
- 通用视觉模型识别和基于截图的坐标点击。
- LangGraph 的第二套完整实现。
- 追求所有公开网站上的通用成功率。

## 3. 成功标准

改造完成需满足以下条件：

1. 本地确定性任务集至少覆盖信息检索、多步导航和表单填写三类任务。
2. 导航、点击、输入、回车、滚动均有可执行实现，并共享同一元素标识体系。
3. 非法模型输出、缺少参数、找不到元素、页面超时和步数耗尽均产生明确状态和错误信息。
4. Streamlit 能展示任务执行轨迹、每步截图、总耗时和最终状态。
5. 核心解析、状态转换、元素定位及验收逻辑具备自动化测试。
6. 评测命令可输出每项任务结果、成功率、平均步数、平均耗时和失败分类。
7. README 中提供安装方法、架构说明、演示任务、评测方法和已知限制。

不预先承诺成功率数值。简历中只使用实际评测后得到的数据。

## 4. 总体架构

系统分为五个职责清晰的部分：

1. **Agent Runner**：维护任务上下文和执行循环，调用模型，校验动作，调度工具，并决定继续、成功或失败。
2. **Action Protocol**：定义模型可返回的动作类型、参数和解析规则，将不确定的文本输出转换为可校验的数据。
3. **Browser Controller**：封装 Playwright 生命周期及浏览器操作，对上层返回统一的执行结果。
4. **Page Observer**：提取页面标题、URL、正文摘要和交互元素，并为当前快照生成统一元素标识。
5. **Trace and Evaluation**：记录步骤和指标，向 Streamlit 与离线评测程序提供统一数据。

依赖方向为：Streamlit／评测入口调用 Agent Runner；Agent Runner 依赖模型适配器、Action Protocol 和 Browser Controller；Browser Controller 内部使用 Page Observer；各层只通过结构化数据通信。

## 5. 数据模型与接口

### 5.1 页面观察

页面观察结果包含：

- `title`：页面标题。
- `url`：当前地址。
- `text`：经过长度限制的可见正文。
- `elements`：当前快照中的可交互元素列表。
- `observation_id`：当前页面观察快照标识。

每个元素至少包含：

- `element_id`：在当前快照中唯一的整数标识。
- `tag`、`role`、`type`：元素类型信息。
- `text`、`aria_label`、`placeholder`：供模型理解的语义信息。
- `href`：链接地址，仅在适用时存在。
- `disabled`：是否不可操作。

Page Observer 在真实 DOM 节点上写入内部属性，将 `element_id` 与节点绑定。点击和输入均通过同一内部属性定位。每次页面导航、点击、输入、回车或滚动完成后重新观察页面，旧 `observation_id` 和元素标识失效。

### 5.2 动作协议

模型每轮只返回一个 JSON 对象。动作集合为：

- `navigate`：参数 `url`。
- `click`：参数 `element_id`。
- `type`：参数 `element_id`、`text`。
- `press_key`：参数 `key`，第一阶段仅允许 `Enter`。
- `scroll`：参数 `direction`，允许 `up` 或 `down`。
- `finish`：参数 `result` 和 `evidence`。

解析器允许从 Markdown 代码块中提取 JSON，但不再依赖 `ACTION:` 文本正则作为主要协议。动作类型和参数在执行前校验；非法输出形成可恢复错误并反馈给模型。连续达到解析失败上限后，任务以 `invalid_model_output` 结束。

第一阶段继续使用 Qwen-Agent 的聊天模型接口，以 JSON 协议获得结构化行为。是否切换到框架原生 Function Calling，要以当前安装版本的实际接口与稳定性验证结果决定；无论底层调用方式如何，上层动作数据模型保持不变。

### 5.3 执行结果

每次工具执行返回统一结果：

- `ok`：是否成功。
- `action`：已执行动作。
- `observation`：执行后的页面观察；失败且页面仍可用时也返回。
- `error_code` 和 `error_message`：失败分类及说明。
- `duration_ms`：工具执行耗时。
- `screenshot_path`：该步骤截图路径。

### 5.4 任务结果

任务状态限定为：

- `running`
- `succeeded`
- `failed`
- `max_steps_exceeded`
- `cancelled`

任务结果包含最终状态、模型结果文本、失败原因、步骤轨迹、总耗时和截图列表。`succeeded` 只表示 Agent 按协议结束；在评测模式下还必须经过场景验收器，才能计入任务成功率。

## 6. Agent 执行流程

1. 启动浏览器并生成初始空白页观察。
2. 将用户任务、动作协议和当前页面观察发送给模型。
3. 解析并校验模型返回的单个动作。
4. 若为浏览器动作，则执行工具、截图、重新观察页面并记录轨迹。
5. 若动作失败，将结构化错误和最新观察反馈给模型，允许其重新决策。
6. 若为 `finish`，在交互模式中返回结果；在评测模式中继续运行场景验收器。
7. 若超过最大步数、连续解析失败上限或重复无效动作上限，则以明确失败状态终止。
8. 无论成功或异常，都在 `finally` 路径关闭页面、浏览器和 Playwright 资源。

重复动作以动作类型、参数、URL 和观察摘要组合判断。相同动作在相同页面状态下连续失败达到阈值时终止，避免消耗无意义的模型调用。

## 7. 错误处理

错误分为以下类型：

- `invalid_model_output`：模型输出无法解析或参数不合法。
- `stale_element`：元素属于旧页面观察或当前已不存在。
- `element_not_found`：当前观察中不存在指定元素。
- `navigation_timeout`：页面导航超时。
- `browser_error`：Playwright 或浏览器生命周期异常。
- `repeated_action`：模型在相同状态重复无效操作。
- `max_steps_exceeded`：达到最大执行步数。
- `evaluation_failed`：Agent 声明完成但场景验收未通过。

可恢复错误会反馈给模型，并携带最新页面观察。不可恢复错误和达到重试上限的错误终止任务。日志与用户界面显示简洁错误说明，同时保留结构化错误码用于统计。

## 8. Streamlit 界面

界面保留侧边栏配置和聊天式任务输入，并增加：

- 当前任务状态、已执行步数和累计耗时。
- 步骤时间线：动作、参数、执行结果和错误信息。
- 每一步的页面标题、URL 和截图。
- 最终结果与结构化失败原因。
- 预设演示任务，方便面试时一键复现。
- 最近一次执行轨迹的 JSON 下载。

Agent Runner 通过步骤回调报告事件。Streamlit 使用回调更新占位容器，使长任务执行过程中可以看到进度，而不是等待整个同步调用结束后一次性显示。

API 密钥只用于当前进程中的模型调用，不写入任务轨迹、截图、日志或导出文件。

## 9. 演示任务与评测

仓库新增本地演示站点或静态页面，提供确定性内容和交互，避免公开网站改版导致基础验收不稳定。

固定任务集包括：

1. **信息检索**：搜索指定关键词，返回满足条件的条目及详情信息。
2. **多步导航**：从列表页进入匹配项详情页，提取指定字段。
3. **表单填写**：根据自然语言填写多个字段并提交，验收提交后的页面内容。
4. **错误恢复**：提供相似元素或失效入口，验证 Agent 是否能根据错误重新决策。

每个场景包含任务文本、最大步数和确定性验收器。验收器通过最终页面 URL、DOM 内容或表单提交结果判断成功，不采用模型自评作为通过依据。

评测输出：

- 总任务数和成功任务数。
- 任务成功率。
- 平均执行步数。
- 平均任务耗时。
- 各类失败数量。
- 每个任务的轨迹文件路径。

公开网站案例仅作为扩展演示，并在 README 中注明网络、站点结构和反自动化策略可能影响结果。

## 10. 测试策略

测试分为三层：

1. **单元测试**：动作 JSON 解析与校验、状态转换、重复动作检测和错误分类。
2. **浏览器集成测试**：针对本地演示页面验证观察、统一元素定位、点击、输入、回车、滚动和资源关闭。
3. **Agent 场景测试**：使用脚本化假模型返回固定动作序列，验证完整执行循环与确定性验收器，不消耗真实 API 配额。

真实 Qwen 模型评测与自动化测试分开运行。前者用于产生项目指标，后者用于保证代码修改不会破坏核心链路。

## 11. 代码结构调整

计划形成以下结构：

```text
src/
  agent/
    runner.py             # 执行循环与任务状态
    protocol.py           # 动作和结果数据模型、解析与校验
    prompts.py            # 系统提示和页面观察格式化
  browser/
    controller.py         # Playwright 生命周期与动作执行
    observer.py           # 页面观察和元素标识
  app/
    streamlit_app.py      # 可视化界面
  evaluation/
    runner.py             # 评测执行和指标汇总
    scenarios.py          # 固定任务及验收规则
  demo/
    site/                 # 本地确定性演示页面
    run_demo.py           # CLI 演示入口
tests/
  unit/
  integration/
```

为控制改造风险，迁移期间保留兼容导入入口；调用方切换后再删除重复实现。不会保留两套长期并行的浏览器控制器。

## 12. 文档与简历输出

README 最终应说明：项目定位、架构图、运行方法、演示任务、评测命令、实测指标和已知限制。简历描述以最终实现和评测结果为准，建议覆盖：

- 设计模型决策、工具执行和页面反馈闭环。
- 实现统一元素标识、结构化动作校验和失败恢复。
- 使用 Streamlit 展示执行轨迹、截图和任务结果。
- 构建确定性任务集，以实际数据报告成功率、步数和耗时。

LangGraph 对比只有在第二阶段完成相同工具、相同任务和相同指标的实验后才写为“实现并对比”；否则表述为“调研并分析”。

## 13. 实施顺序

1. 建立动作协议、任务状态和单元测试。
2. 重构页面观察与浏览器控制，补齐浏览器集成测试。
3. 重构 Agent Runner，使用假模型完成端到端场景测试。
4. 建立本地演示站点、验收器和评测命令。
5. 改造 Streamlit 执行轨迹界面。
6. 使用真实 Qwen 模型运行评测并记录结果。
7. 修订 README 和简历描述。

真实模型评测需要有效的 DashScope API 密钥和可用网络。其他开发与测试应能在不调用外部模型 API 的情况下完成。
